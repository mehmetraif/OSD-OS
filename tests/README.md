# Regression tests

Thirty-four test suites, built apart from the app; one of them starts the app itself, on the main menu and on each module. CI runs them on Linux x64 and arm64 for every pull request that touches `src/`, `scripts/`, `Main.qml`, `views/`, `modules/`, `assets/`, `shaders/`, `tests/`, `thirdparty/` or the build ([regression-tests.yml](../.github/workflows/regression-tests.yml)): on Ubuntu, with the oldest Qt the releases are built with (6.4), and on Raspberry Pi OS (Debian 13 "trixie" with Raspberry Pi's archive, arm64), the system the OS image is made of, with the Pi's own Qt (6.8) and mpv (0.40). The release workflow runs them too, on the tagged commit, and publishes no release that fails them, though its builds are made ([release.yml](../.github/workflows/release.yml)); and the FreeBSD and OpenBSD build workflows run them in their virtual machines, with the systems' Qt 6.11 ([freebsd.yml](../.github/workflows/freebsd.yml), [openbsd.yml](../.github/workflows/openbsd.yml)). They need Lua 5.4, CMake, a C++17 compiler, Qt 6's development packages (Core, Concurrent, Gui, Network, Qml, Quick, QuickTest and Test) and SDL2's, libdrm's on Linux, zlib's and minizip's for **highscores** (`libminizip-dev`; without them that suite is left out, with a warning), and Qt's D-Bus module (in `qt6-base-dev`) and `dbus-daemon` for **wifi** (without the module that suite is left out, with a warning; without `dbus-daemon` it skips itself); the QML tests also need Qt Quick's QML modules at run time (on Debian and Raspberry Pi OS, `qml6-module-qttest qml6-module-qtquick qml6-module-qtqml-workerscript qml6-module-qtquick-window`). None needs mpv, FluidSynth, MAME, NetworkManager or a display. The **app** tests start the app, built first in `build/` as [BUILDING.md](../BUILDING.md) has it (`-DOSDOS_APP=<path>` for one elsewhere), with the QML modules it runs with (a module that imports one this Qt doesn't have is skipped; but Qt Quick 3D, which only the Arcade screen's Orb look imports, and which the app goes on without).

```sh
cmake -S tests -B build-tests
cmake --build build-tests --parallel
ctest --test-dir build-tests --output-on-failure
```

A QML test (`qml/tst_*.qml`) is added with `osdos_qml_test(<name> <file>)` in `CMakeLists.txt`, which runs it on tree_browser's runner, offscreen, with the software renderer, `views/` and `stubs/` to import. Its root is `StandInRoot { id: root }` (`stubs/OSDOS/Testing/StandInRoot.qml`, `import OSDOS.Testing`): `Main.qml`'s root as the views and their shared components read it (`root.*`), with `Main.qml`'s values on a 640×480 screen in the Standard layout, white on black, the effects resting, and the monitor layouts' frame (`root.chrome`). The test sets in it what it has otherwise (its size, a layout, its colours) and declares its own stand-ins beside it. Something new a shared component reads of `Main.qml`'s root goes into `StandInRoot`, once. Only **window_change** has a root of its own: it stands in for the part of `Main.qml` that changes the views, which `StandInRoot` does at once, or for a test that sets `changesDeferred` a moment later, as a transition has it.

A C++ test built with the app's sources links those several tests share, built once as static libraries: `osdos_test_names` (`util/LegacyNames`), `osdos_test_core` (`AppCore` and the files it reads and writes through), `osdos_test_audio` (`audio/`: Audio Output, the menu music and the other mpvs beside it) and, on Linux, `osdos_test_system` (`util/Board`, `util/RootRequest`), `osdos_test_launch` (`ScriptLauncher`, `ControllerProfile`, `DisplayHandoff`, `YtDlpLocator`) and `osdos_test_youtube` (YouTube and the web player). A source goes into one only while no test builds it with a definition of its own.

  - Skipped without the app, and for a module that imports a QML module of Qt's the Qt in use doesn't have.
- **app_core_info** (`app_core_info_test.sh`, where the arcade test's core is built): the app asked a libretro core's name and version (`--core-info`), as the Arcade module asks a copy of it, with nothing of an environment (no display, no platform for Qt, no data folder): it prints the test core's (`arcade_test_core`), and refuses a file that isn't a core, saying why. - **retroarch_tls** (`retroarch_tls_test.sh <retroarch>`, as root; not one of `ctest`'s, the `retroarch` action runs it on a new build): the RetroArch OSD/OS builds for its Linux arm64 package (`scripts/build-retroarch.sh`), started on a game with a core of the test's (`retroarch_tls/core.c`) against a stand-in for RetroAchievements' site (`retroarch_tls/server.py`), in a mount namespace where the certificates file has the test's roots and `/etc/hosts` names this machine as the site.
  - With a good certificate (an EC chain, an RSA one with chunked answers, an EC one under an RSA root) it asks over https on its own, signs in, earns an achievement and keeps the token.
  - With one signed by a root the system doesn't trust, one for another name and one out of date, it asks nothing of the site, so the password stays on the machine, and says the sign-in failed. A RetroArch built with mbedTLS fails these three.
  - Skipped (77) without root, python3, openssl, a C compiler or `unshare`.

## A stand-in NetworkManager for screenshots

`fake_networkmanager`, built with the tests and never run by ctest, is **wifi**'s stand-in on its own. It registers as NetworkManager on the bus whose address it is given, else the one `DBUS_SYSTEM_BUS_ADDRESS` names, and runs until it is killed, with five networks heard: Home, saved and joined; Workshop, saved; Arcade Hall (WPA3, password `insert-coin`), Corner Cafe (open) and Neighbours (WPA, password `not-yours-42`), each with its own number of bars. Each step of joining takes a second and a half, so that a network on its way can be seen. The app shows them in Settings → Network → Wi-Fi with that bus as its system bus (on Linux, the app built with Qt D-Bus, without `OSDOS_AUTOSTART`):

```sh
export DBUS_SYSTEM_BUS_ADDRESS=$(dbus-daemon --session --fork --print-address=1)
build-tests/fake_networkmanager &
APP_ROOT=$(pwd) ./build/osdos
```

For the country's line, point `OSDOS_BOOT_DIR` at a folder whose `cmdline.txt` has `cfg80211.ieee80211_regdom=GB`. Kill the stand-in and that `dbus-daemon` once done.
